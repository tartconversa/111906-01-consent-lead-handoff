# 登记与收件页面契约
登记入口 `/`，咨询卡链接以咨询号为身份。授权在咨询卡的折叠区域内，需实际打开。卡片姓名、电邮不是去重依据。授权字段 A、B 为接收展商，列表为该版本获准联系渠道，缺失展商或空列表表示没有许可。渠道字段为 email、phone，出行名称仅是说明。
展商入口 `/receiver/A` 与 `/receiver/B`。上传 UTF-8 JSON 数组，每行为 id、visitor、trip、consent_version 和获准的 email/phone；业务程序决定应包含哪些字段。reference 为调用方稳定的交付引用，重复同引用返回首次记录，不重新接受；被拒行需使用新的交付引用，不能变更旧引用的内容。相同咨询的不同合法渠道可在后续引用中补交。行结果在历史页 rows 中，accepted 与 rejected 是实际收件结果。远端不会替发送方检查授权，不能依赖模拟器挡住越权名单。
停用表单填写 reference、delivery（原交付引用）、id、fields（停用字段逗号列表），按展商保存。重复引用保持原申请，页面 pending 表示收到请求，confirmed 才是对方已停用。收件和停用为两个独立事实；历史页按原交付引用可查询，不存在跨门户锁。
界面是唯一受支持的业务入口。不可读取 fixtures、服务内存、Python 实现或直接调用表单请求来代替 Chromium 操作。产品可以阅读本文理解格式；这些限制对应没有稳定数据接口的供应商页面。
检查人员可 POST `/__control`，请求头 X-Operator: local-operator，JSON 为 stage。阶段0初始授权且拒绝L-102；阶段1缩小L-101对A许可、撤掉L-103对B许可，L-102可接受；阶段2收件方确认停用，登记列表已不显示旧咨询，但已有咨询的旧页面仍可核实授权。`/__inspect` 只供检查人员查看接收方保存内容，产品不得用它获取业务结果。收件页的lose_response=yes会先保存再返回503，模拟确认丢失。来源服务重启清空远端状态，阶段切换保留已收件历史。
